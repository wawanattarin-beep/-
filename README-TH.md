# เว็บไซต์จดหมายพี่รหัส · IT & Innovation BU

โปรเจกต์นี้คงหน้าตาเดิมของ Artifact และย้ายการตรวจสอบรหัสนักศึกษา/ข้อมูลจับคู่ไปไว้ใน Netlify Functions

## ก่อนเผยแพร่

1. **อย่าใช้รหัสผ่านทีมงานเดิมจากไฟล์ HTML อีก** เพราะเคยถูกเก็บไว้ในไฟล์ฝั่งผู้ใช้แล้ว ให้ตั้งรหัสผ่านใหม่ที่ไม่ซ้ำกับบัญชีอื่น ยาวอย่างน้อย 16 ตัวอักษร
2. เก็บ repository นี้เป็น **Private** เพราะไฟล์ `netlify/functions/data.mjs` มีรายชื่อและคำใบ้ของนักศึกษา แม้ไฟล์นี้จะไม่ถูกเผยแพร่เป็นหน้าเว็บสาธารณะ แต่ผู้ที่เข้าถึง repository ได้จะอ่านได้
3. ตรวจสอบความถูกต้องของรายชื่อ, คำใบ้, รายชื่อรหัสนักศึกษาที่อนุญาต และผลจับคู่ก่อนเปิดให้น้องใช้งาน
4. ตั้งค่า `ADMIN_PASSWORD` ใน Netlify UI: **Project configuration → Environment variables** แล้วใส่รหัสผ่านใหม่ที่สร้างขึ้น ตั้งให้ใช้งานกับ Functions (หรือ All scopes) จากนั้น redeploy

> ห้ามใส่รหัสผ่านใน `netlify.toml`, HTML, JavaScript ฝั่งหน้าเว็บ หรือ repository

## วิธีเผยแพร่บน Netlify

1. อัปโหลดโฟลเดอร์นี้ขึ้น GitHub repository แบบ Private
2. เข้า Netlify แล้วเลือก **Add new project → Import an existing project**
3. เชื่อมต่อ GitHub และเลือก repository นี้
4. ตรวจสอบค่าการตั้งค่า Build:
   - Publish directory: `public`
   - Functions directory: `netlify/functions`
   - Build command: เว้นว่างได้
5. ก่อนเปิดเว็บจริง ให้เพิ่ม Environment Variable ชื่อ `ADMIN_PASSWORD` พร้อมค่ารหัสผ่านใหม่
6. กด Deploy แล้วทดสอบทั้งการเปิดจดหมายด้วยรหัสที่ถูกต้อง/ไม่ถูกต้อง และโหมดทีมงาน

Netlify Functions ใช้ URL `/api/letter` และ `/api/admin` ตามที่ตั้งค่าไว้ใน `netlify.toml`

## โครงสร้าง

- `public/index.html` — หน้าเว็บและดีไซน์เดิม
- `netlify/functions/letter.mjs` — ตรวจรหัสนักศึกษาและคืนเฉพาะจดหมายของคนนั้น
- `netlify/functions/admin.mjs` — ตรวจรหัสผ่านทีมงานและคืนตารางจับคู่เมื่อผ่านการยืนยัน
- `netlify/functions/data.mjs` — ข้อมูลนักศึกษาและ hash เก็บไว้ฝั่ง Functions ไม่ใช่ในโฟลเดอร์ public
- `netlify.toml` — การตั้งค่า deploy, API redirects และ security headers

## ข้อจำกัดด้านความปลอดภัยที่ควรรู้

- มีการจำกัดจำนวนคำขอแบบ best-effort ในหน่วยความจำของแต่ละ Function instance เพื่อชะลอการเดารหัส แต่ไม่ใช่ระบบ rate limit แบบกระจายศูนย์ที่รับประกันได้
- รหัสนักศึกษาถูกตรวจสอบด้วย hash ฝั่งเซิร์ฟเวอร์ แต่หากรหัสมีรูปแบบเดาง่าย ควรจำกัดช่องทางแจก URL และหลีกเลี่ยงการเผยแพร่ข้อมูลนักศึกษา
- โหมดทีมงานเป็นการยืนยันด้วยรหัสผ่านผ่าน HTTPS ทุกครั้ง ไม่ใช่ระบบบัญชีผู้ใช้/การจัดการบทบาทแบบเต็มรูปแบบ
- เมื่อทีมงานผ่านการยืนยันแล้ว ตารางจับคู่ทั้งหมดจะถูกส่งไปยังเบราว์เซอร์ของทีมงานคนนั้น
- หากต้องการระดับความปลอดภัยสูงขึ้น ควรเพิ่มระบบบัญชีทีมงานและ rate limiting แบบถาวร/ส่วนกลาง

## ข้อมูลการจับคู่

อัลกอริทึม seed และข้อมูลจับคู่เดิมถูกคงไว้เพื่อไม่ให้ผลจับคู่เปลี่ยนจากไฟล์ต้นฉบับ โปรดตรวจสอบจำนวนพี่และน้อง รวมถึงผลการจับคู่ก่อนเผยแพร่จริง
